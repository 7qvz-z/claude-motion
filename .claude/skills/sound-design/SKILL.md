# Sound design

Most AI-made motion graphics are silent. Sound is what makes this one feel produced.

All audio is generated by `scripts/sfx.py` (pure Python stdlib, no samples, no licenses to worry about) from the same `timeline.json` the visuals use. Output: `public/sfx.wav`, muxed into the final MP4 by `npm run mux`.

## The rule

A sound is `put(time, samples, gain, pan)` where `time` comes from a timeline key. Never type a raw number for when something happens; if the picture moves, the sound moves with it.

## Visual event → sound

| On screen | Sound | Generator |
|---|---|---|
| Typing | one key per character, ±4–6 ms jitter, random gain 0.14–0.26 | `key()` |
| Word / line reveal | short airy whoosh + low blip on the landing | `whoosh()`, `blip()` |
| Element pops in (badge, chip, callout) | pitched pop, rising pitch across a sequence | `pop()` |
| Control snaps to a step | click + a note from the scale | `click()`, `blip()` |
| Sketch / draw-on | pencil scratch texture | `scratch()` |
| Progress / build-up | riser into the payoff (one per video) | `riser()` |
| Success / arrival | bell chime in key | `chime()` |
| Hero transition | whoosh in, low impact on the hit (one per video) | `whoosh()`, `impact()` |
| Under everything | quiet pad chord, ducked under transitions | `pad()` |

Accent, don't narrate: not every motion needs a sound. Continuous motion (drift, grain, rotation) stays silent.

## Levels

- Hero hits (pops, impact, key moments): gain 0.25–0.35.
- Supporting (whooshes, blips, chimes): 0.08–0.2.
- Bed (pad): ~0.03, ducked by ~65% during the hero transition and lifted after.
- Only one impact per video. Only one big riser.

## Space and music

- Pan roughly follows on-screen position (−1 left … +1 right); sequences sweep across the stereo field.
- Pick one key and keep every tonal sound in it. In the effort video the pad (D–A–D–F♯–C♯) and the slider notes (E5–F♯5–A5–B5) are in D major; the scene 3 pops and chime are still in C major, so fix those before copying them.
- Pitch rises with progress (steps, pops) and resolves on the payoff chord.
- Seed the RNG (`random.seed(...)`) so renders are reproducible.

## Mastering

- Normalize, soft-clip with `tanh`, 0.25 s fade-out (already in `sfx.py`). `DRIVE` sets loudness, `CEIL` sets headroom; tune them together and re-measure the muxed MP4, AAC overshoot isn't linear.
- Target **−14 LUFS integrated** (X, Instagram, YouTube all normalize near this).
- Keep **true peak ≤ −1 dBFS**. AAC encoding in `mux` adds overshoot, so the final MP4 peaks higher than the WAV.

## Verify

```bash
npm run sfx          # regenerate public/sfx.wav
npm run wave         # out/wave.png + loudness of the WAV
npm run build        # full render + mux
node scripts/wave.mjs out/effort.mp4   # loudness of what you'll actually post
```

In `out/wave.png` every coral line is a timeline beat. Each transient should sit on a line or a hair after it. A hit between lines means a hardcoded time or a stale WAV.

## Optional: generated audio

For voiceover or sounds you can't synthesize, the ElevenLabs MCP (see `.mcp.json.example`) can generate SFX/TTS into `public/`. Place them with `<Audio src={staticFile(...)} />` inside a `<Sequence from={beat * FPS}>`, or mix them into `sfx.py` so everything stays one master.
